`cargo test --all-features --test bridge_acceptance -- --test-threads=1`

このテストは未完成の機能を失敗させる受入ゲートです。`ignore`、`should_panic`、GPU不在時の成功扱いはありません。既存CIの `cargo test --all-features` に含まれます。現在の実装で全件成功することは期待していません。

## 動作を検査する範囲

- CLIを子プロセスで起動し、出力PNGをCPUの基準レンダーと比較する。複数コンポジションのアクティブ選択、保存したDocumentのBindingを0・12・24フレームで確認する。
- CLIの連番レンダーでキーフレームアニメーションの全フレーム・包括的な範囲端・PNG生成を照合する。逆順範囲、尺外フレーム、0幅は失敗し、部分出力を作らないことも確認する。
- プロジェクト保存・CLI読込をまたいで全29種類のBlendModeを積層し、レイヤー順を含む画素結果を照合する。各アニメーションフレームも同一画像へ潰れていないことを確認する。
- CLI GPU出力をCPU出力と比較する。異なる2つのColor Tintを順に適用し、1つを無視した出力では通らない。許容差は各RGBAチャンネル最大2。GPUが利用できない場合もゲート失敗。
- 対応する通常レイヤー＋Screen合成のシーンで、CLIログに実WGPU経路の使用が記録されたことを要求してからCPU画素と比較する。CPUフォールバックでGPU合格を偽装できない。現在この実GPU比較は最大チャンネル差174で失敗する。
- 29種類のBlendMode検査はCLI側の保存・再読込とCPU描画を比較し、GPUでfallbackするケースと実GPU検査を別々に判定する。
- 標準OTIOスキーマの生成と再読込で画素を比較する。
- Dynamic Linkの実TCP接続・Handshake・再生位置受信を確認する。ポートはOS割当の0を使用し、待機上限は2秒。サーバーには停止APIがないため、listenerはテストプロセス終了時に終了する。
- Dynamic Linkの素材追加・レンダー要求は、有効な素材ファイルと初期コンポジションIDを使い、未実装エラー・無応答を失敗にする。この検査だけではGUIへの素材追加・生成画素までは証明しない。
- Documentを同じファイルへ再保存し、再読込したBindingの値と画素が変化することを確認する。常駐Previewウィンドウのファイル監視・表示更新はこのテストの対象外。
- 実OFXプラグインをロードし、参照画像と画素一致を確認する。
- 実AIモデルをロードし、参照マットと一致する推論出力を確認する。

## 実フィクスチャ

OFXには `KAGARI_TEST_OFX_PLUGIN`、`KAGARI_TEST_OFX_INPUT`、`KAGARI_TEST_OFX_EXPECTED` が必要。0フレーム・既定パラメータでの出力を参照PNGとする。入力と出力が同一の素通しフィクスチャは拒否する。

AIには `KAGARI_TEST_AI_MODEL`、`KAGARI_TEST_AI_INPUT`、`KAGARI_TEST_AI_MATTE` が必要。CPU実行・プロンプトなしでの参照マットを用意する。入力RGBと同じ寸法の8bitグレースケールPNGを使用する。

フィクスチャ未設定は失敗する。現在はライセンス確認済みの実プラグイン・モデルを同梱していないため、実フィクスチャを用意しないCIはこのゲートを通過できない。

## 未接続箇所の構造ゲート

公開された統一実行APIがまだない箇所は、移行中の構造ゲートで検出する。

- アプリ描画経路からRenderPipelineを生成する呼出しがあること。
- AEホストがアプリまたはレンダー実行経路に接続されていること。
- ファイルメニューが標準OTIOの `from_json` / `to_json` を通り、先頭コンポジションを固定上書きしないこと。
- 2つのAE定義でRenderコマンド・EffectWorldのサイズ・画素ポインタ位置が一致すること。

構造ゲートはソースの呼出しを検査する補助検査で、実行成功の証明ではない。コード移動・API改名時は検査も更新が必要。公開実行サービスを導入したら、実ジョブの完了結果・画素比較へ置き換える。AEの公式SDKとのABI一致、実ネイティブプラグインのロードから描画まで、GUIでのジョブ反映は追加の実行検証が必要。
